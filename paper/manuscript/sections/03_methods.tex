\section{Data, Forecasting, and Recommendation Method}

\subsection{Data and Information Available at Prediction Time}

The source is the cleaned LBNL Building~59 release described by Luo \emph{et al.}~\cite{Luo2022} and distributed through Dryad~\cite{Hong2022}. The repository retains one selected south-zone subset and resamples the imported streams to 15-min bins. An interval receives the camera-derived occupied label when the maximum selected south-zone camera count is greater than zero. The analysis flips this label so that $y_{d,t}=1$ denotes \emptyclass{} and $y_{d,t}=0$ denotes camera-labeled occupied. The dataset therefore operationalizes \emptyclass{} as zero detected occupants in the selected camera counts. Independent physical-presence validation is a future data-collection step. The analysis contains 26,413 local-time rows from May~2018 through February~2019. Table~\ref{tab:protocol} gives the exact split and policy scopes.

Naive source timestamps are interpreted as UTC and converted to \texttt{America/Los\_Angeles} before time features are formed. A solar-radiation peak sanity check supports this interpretation; the source documentation leaves the timestamp timezone unspecified. Each resampled record uses a left-closed, left-labelled convention: its label $t$ denotes $[t,t+15\text{ min})$. The tabular and sequence models consume the completed anchor record, giving an effective availability boundary of $t+15$ min. The first target bin begins at that boundary, and a 96-step horizon spans $[t+15\text{ min},t+24\text{ h}+15\text{ min})$. A policy anchor labelled 00:00 therefore becomes available at 00:15 and targets the following 96 bins.

Calendar variables are known for future target times. The tabular information set comprises past occupancy/count lags and rolling summaries, completed-input-bin Wi-Fi, temperature, and weather values, and target-time calendar variables. After import, environmental and association-count sensors are forward-filled in row order; leading missing values are set to zero. Repository-level imputation provenance begins after import of the cleaned release. Wi-Fi has 81.57\% missingness before the unlimited row-order forward fill. The post-forecast opportunity calculation uses the retained HVAC and lighting series; other electrical-load streams and their aggregate remain outside the analysis.

Each rolling forecast uses 96 historical 15-min intervals and predicts the next 96 intervals. Chronological train, validation, and test segments are separated by 24.25-h gaps, keeping every saved forecast history and target window within its assigned split. Fitting, policy selection, and held-out saved-output evaluation therefore use distinct temporal segments.

\subsection{Forecast Models and Why Use a Hybrid}

The comparison includes a historical weekday/time-slot average fitted on the training partition, LightGBM, random forest, a direct linear occupancy baseline (legacy artifact key \texttt{DLinear}), and a compact Transformer encoder (legacy artifact key \texttt{Original Transformer}). Table~\ref{tab:model-settings} gives the stored implementation settings. The saved outputs are bounded $[0,1]$ Empty-class scores, denoted by $p$. The pipeline stores them as raw, uncalibrated scores. Historical runs bear seed labels 42, 43, and 44, and their stored scores are pointwise averaged. Deep modules were instantiated before the seed-reset function, so controlled seed-dispersion analysis requires corrected retraining.

The hybrid combines three sources of predictive structure. The historical model represents the building's recurring weekday and time-of-day schedule. LightGBM represents nonlinear relationships among lagged occupancy, sensor, weather, and calendar features. The compact Transformer represents patterns across the recent 96-interval sequence. A single validation step combines the stored component outputs.

The saved primary hybrid blends the three component Empty-class scores. For time $t$ it is
\begin{equation}
p_{\mathrm{H}}(t)=0.15p_{\mathrm{hist}}(t)+0.60p_{\mathrm{LGBM}}(t)+0.25p_{\mathrm{Tr}}(t),
\label{eq:blend}
\end{equation}
where the nonnegative weights sum to one. These values attain the maximum validation AUPRC on a declared 0.05 simplex grid of 231 legal weights. The pipeline loads test scores after this canonical selection and preserves the fitted component models. Section~V-B evaluates the small separation among validation candidates.

Forecast selection and recommendation selection answer different questions. The weight search uses validation AUPRC to choose a score that ranks Empty intervals. After those weights are fixed, the threshold search described next chooses when to act by balancing two policy quantities: the observed camera-label conflict rate and the offline load-opportunity proxy. Both selection steps use validation data, and the pipeline fixes their outputs before reading test conflict and opportunity outcomes.

\subsection{From Forecast Scores to One-Hour Recommendations}

For a model-specific score threshold $\tau$, define an initial recommendation $b_{d,t}=\mathbf{1}\{p_{d,t}\geq\tau\}$. Let $L=4$ be the number of 15-min intervals in one hour. The policy recommendation $r_{d,t}$ equals one when $b_{d,t}$ belongs to a contiguous run of at least $L$ intervals within a midnight-labelled daily horizon. Runs are extracted independently within each 24-h forecast horizon. The interval camera-label-conflict rate is
\begin{equation}
C=\frac{\sum_{d,t}r_{d,t}(1-y_{d,t})}{\sum_{d,t}r_{d,t}},
\label{eq:conflict}
\end{equation}
For an empty recommendation set, define $C=0$.

Let $\widetilde{h}_{d,t}$ and $\widetilde{\ell}_{d,t}$ denote the processed south-HVAC and south-lighting meter streams, respectively, in nominal kW. Define
\begin{equation}
q_{d,t}=0.25\max(\widetilde{h}_{d,t}+\widetilde{\ell}_{d,t},0),
\label{eq:load-proxy}
\end{equation}
which is a processed meter-derived 15-min load proxy in kWh. The nominal full-metered accounting convention uses a coefficient of one for each stream, and multiplication by 0.25~h converts kW to interval kWh. Each stream is 8.03\% missing before the post-import row-order forward fill, so $q$ includes carried-forward values; its momentary controllability is untested. The paper reports
\begin{equation}
O_{\mathrm{safe}}=\sum_{d,t}r_{d,t}y_{d,t}q_{d,t}.
\label{eq:opportunity}
\end{equation}
Equation~\eqref{eq:opportunity} is an offline overlap measure: it sums the processed load proxy where a recommendation and a subsequently observed camera-derived Empty label coincide. Estimating the effect of a control action would require a counterfactual. For each model, $\tau$ is selected from $\{0.050,0.075,\ldots,0.950\}$ on validation midnight-labelled horizons to maximize $O_{\mathrm{safe}}$ subject to the empirical condition $C_{\mathrm{val}}\leq0.10$, breaking exact opportunity ties by Empty recall. Because $O_{\mathrm{safe}}$ uses realized labels and processed loads, it serves as an offline validation-selection objective. The selected threshold is then fixed for all test policy calculations.
